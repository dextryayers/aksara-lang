# ADR 0003: Manajemen Memori dan GC

## Status

Diterima.

## Konteks

Aksara memiliki objek dinamis, siklus referensi, callback lintas bahasa, dan buffer yang dibagikan dengan NumPy. Runtime harus dapat berinteraksi dengan CPython tanpa menyalin data besar.

## Keputusan

- GC mark-sweep non-moving.
- Root presisi dari stack VM, frame, global, dan objek yang didaftarkan.
- Finalizer dijalankan pada antrean terpisah setelah sweep.
- Objek yang dipin tidak dipindahkan karena tidak ada pemindahan objek.
- Buffer protocol didukung untuk `susunan` dan `numpy.ndarray` tanpa salinan.
- Siklus lintas runtime dibatasi pada v1.0 dan didokumentasikan.

## Konsekuensi

- Alamat objek stabil, sehingga pointer C dan buffer aman.
- Tidak ada compaction, sehingga fragmentasi harus dipantau.
- Write barrier tidak diperlukan karena non-moving dan mark-sweep.
- Siklus yang melibatkan objek Python dan Aksara dapat bocor bila tidak ditutup eksplisit.

## Alternatif yang ditolak

- Reference counting saja: siklus bocor dan biaya atomik tinggi.
- Moving GC: tidak kompatibel dengan pointer C dan buffer NumPy.
- GC generasional pada v1.0: kompleksitas belum sebanding dengan kebutuhan.
